# Domain docs

Layout: single-context.

## Before exploring

- Read CONTEXT.md at the repository root, if present.
- Read relevant decisions under docs/adr/, if present.
- If these documents are absent, proceed silently. Create them only when
  domain-modeling or ADR work establishes actual terminology or decisions.

## Vocabulary and decisions

Use the glossary's terminology when naming domain concepts.
Note genuine terminology gaps for domain-modeling.
Surface conflicts with existing ADRs explicitly, identifying the ADR and
why the decision may need reconsideration.
